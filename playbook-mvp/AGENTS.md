# Playbook MVP 开发约束

本文件作用于 `playbook-mvp/`。先读 [CONTRACTS.md](CONTRACTS.md)、[VALIDATION_STATUS.md](VALIDATION_STATUS.md) 和 [Roadmap](PLAYBOOK_ASK_AI_ROADMAP_v1.md)。用户明确的新指令优先。

## 执行范围

- 一次只执行用户指定的一个阶段。完成后更新验证台账并停止，不自动进入下一阶段。
- 开始前说明计划修改的文件；结束时记录实际修改、实际命令与测试、已满足退出条件、未验证项、下一阶段入口。
- 不改造 ACN、`functional-demo/` 或仓库其他模块，不重做门户 UI。
- 使用 uv 管理 Python。本目录 `.python-version` 固定解释器；命令通过 `uv run python ...` 执行，子进程沿用 `sys.executable`。不向系统 Python 安装包。
- S0 检查只依赖标准库；已有依赖能解决就复用。新增依赖只在实际需要的阶段通过 uv 管理。
- 仓库根有 `.codegraph/` 时，理解或定位代码先用 CodeGraph；无索引不自行创建。未覆盖的文档、配置或代码再直接读取。

## 来源与身份

- 原始 `data/playbook-sampledata.sql` 不改写、不执行。正文和正式关系以它为准；权限语义以已确认业务规则和契约为准。
- 业务身份主输入是 `fixtures/mock_users.json` v2；有效权限由服务端规范化。旧页面 `data/` 中的同名文件只是兼容副本。
- 每个有效身份恰好一个角色：MSFT=1、Partner=2、21V=3。空角色、混合角色、重复角色全部拒绝，不合并或去重后放行。
- 本地业务编号 NCE=0、OSPA=1。MSFT/21V 默认双业务，仍受菜单授权限制；Partner 必须显式拥有一种或两种业务权限。
- 原始业务列表和有效业务列表分别保留，不能直接使用外部系统的反向业务编号。
- 禁止补造 ACL、按标题匹配授权、推断父级继承，或把多菜单默认合并。歧义、缺失、未知状态按契约隔离或拒绝。
- 三个角色当前菜单同权是源数据事实，不制造用户级差异。角色专属反例只能放在独立合成测试中。
- `expected_access.json`、`authorization_cases.jsonl` 是独立权限 oracle，不能作为查询实现、知识正文或前端载荷。禁止为了获得 PASS 修改预期。
- 不沿用旧 Excel 的 42/88 ACL 数量、Document 146 的旧映射或 v1 混合角色身份。

## 授权与开放

- 有效会话、显式实验开放、ACL 可解析必须同时成立；其后才判断 Public 或“角色菜单授权 AND 业务权限”。Public 仍要求有效身份。
- `publication_state=unverified` 和 `lab_release.approved` 分开。禁止将 `Status=1` 改写为已发布，禁止导入后自动开放。
- 管理员仅用于授权的初始化/维护。禁止管理员代替用户查询，禁止管理员读取后在应用或浏览器中过滤。
- 所有用户查询绑定对应 ES 身份；禁止修改共享客户端的全局 Authorization。浏览器只能选择预设 profile，不能自报角色、业务授权、ES DSL 或凭据。
- DLS 必须包含完整访问条件。查询用户只授予统一受限 reader，不能拆成多个角色期待权限取交集，也不能附加无限制 reader。
- 禁止关闭认证、TLS 校验、DLS 或静默降级。DLS、身份或读取接口失败时停止依赖阶段，明确记录问题；替代方案须单独形成决策。
- 凭据不入 Git、不打印、不下发前端；不自动销毁 Docker 数据卷。

## API、页面与验收

- 菜单、搜索、详情、原文、下载均在服务端授权，中英文共享同一 Document ACL。不存在与无权读取采用一致的外部响应。
- 在线版只服务专用静态目录。禁止公开 SQL、ZIP、原文目录、fixture、日志、旧全量 HTML 或预渲染全量正文。
- 禁止全量前端搜索回退。ES 故障显示错误，不放宽权限补足 Top K。
- 切换用户/注销立即清空旧内容，取消请求并校验身份版本与请求序号，拒绝迟到响应；取消请求不能替代服务端授权。
- S3 的真实 ES 权限集合和 S4 的 API 链路通过后才进入 S5。离线 PASS、历史报告、静态 YAML 检查均不能代替这些验收。
- ASK AI 首版是 BM25 文档检索与原文摘录，不实现 LLM 回答、向量、混合检索、Agent 或多轮上下文。
- 权限 oracle 与相关性 Golden Set 分开。未审核的候选问题只用于开发，不宣称搜索质量达标；没有运行的项目明确记为未验证。
- S6 金标已由用户确认并冻结；不得为通过验收修改标注或90%目标。未来扩充使用新的审核版本。
- 同步必须先审核完整快照差异，显式批准开放和删除；失败保持门禁，按原计划重试。正文回滚保留最新ACL、用户授权、撤回及删除，禁止旧索引/文件旁路和旧初始化命令恢复权限。
